# Monk mode — 독립적인 발상과 깊은 수학적 연구

Main Research Lead가 monk로 선택한 연구 과제에 적용한다.
`.codex/guides/research.md`의 연구 품질 기준과 함께 읽으며, 관련 방법론의 조사 범위와
선행연구 대조 시점에는 이 guide를 적용한다. Engineer도 해당 과제를 위임받으면 읽는다.
USER-ONLY 실행, main의 직접 검수, single-writer와 high/xhigh 규칙은 root AGENTS.md를 따른다.

## 목표
- 중요한 문제의 구조와 수학적 원리에서 출발해, 영향력 있는 연구의 축과 novelty가
  있을 법한 방법론을 능동적으로 탐색한다. 핵심 원리·메커니즘·검토 가능한 근거를
  발전시켜, 후속 선행연구 대조에서 실제 남는 기여를 판단할 수 있게 한다.
- 유연하고 기발한 사고와 깊은 분석을 함께 추구한다. 연구의 축은 중요한 질문과
  후속 문제들을 연결하는 중심 원리다. 새로운 능력·방법·문제 설정·설명·한계 규명도
  기여가 될 수 있다. 낯선 이름, 복잡성, 야심찬 표현 자체를 가치나 novelty의 증거로 삼지 않는다.
- 아래 기준은 질문에 맞게 적용한다. 고정된 발상 순서·후보 수·검색 횟수·novelty 점수를
  강제하지 않으며, 모든 응답에 전체 양식을 출력하지 않는다.

## 선택·재개·전환
- 연구 모드는 `standard` / `monk`이며, 연구 논의·리뷰·구현·결과 해석의 작업 모드와 별개다.
  별도 agent나 Codex 설정 key를 추가하지 않고 main의 연구 방식으로 사용한다.
- 사용자가 “이 문제는 monk mode로 연구하자”처럼 선택하면 해당 연구 과제에 적용한다.
  선택이 없는 새 과제는 standard다. 설치·guide 열람·monk에 대한 설명 요청만으로 활성화하지 않는다.
- Main은 적용 과제와 선택 근거를 STATE에 기록하고 재개 시 복원한다.
  구현이나 결과 해석으로 작업 모드가 바뀌어도 같은 과제의 monk 제한은 유지한다.
  다른 과제에 자동 확장하지 않으며 최신 명시적 사용자 선택을 따른다.
- Main은 engineer 생성·재사용 시 연구 모드, 적용 범위, 허용 자료와 이 guide 경로를 전달한다.
  진행 중 모드가 바뀌면 관련 thread에도 변경을 전달하고 새 범위가 반영됐는지 확인한다.
  Engineer는 조사 제한을 독자적으로 해제하지 않는다.
- 막혔거나 후보가 유망해졌다는 이유로 agent가 자동 해제하지 않는다.
  사용자가 “이 후보를 이제 선행연구와 비교하자”라고 요청하면 해당 과제를 standard로
  전환해 요청한 대조를 수행한다. 이 명시적 요청에 추가적인 형식적 승인을 요구하지 않는다.
  전환은 STATE와 위임에 반영하고, 이후 monk 재선택도 같은 방식으로 처리한다.
- Monk 유지와 금지된 조사를 동시에 요구해 범위가 충돌하면 해당 조사 범위만 확인한다.
  독립적으로 가능한 추론은 계속한다. 자료 링크가 있다는 이유만으로 모드를 바꾸지 않는다.

## 조사 경계
- 새로운 외부 연구 조사는 수학적 기법·관점·사고·정리·증명·반례 탐색에 한정한다.
  허용 여부는 발표 연도나 자료의 분류보다 찾으려는 내용과 목적을 기준으로 판단한다.

| 자료·활동 | Monk에서의 처리 |
| --- | --- |
| 합의된 문제·정의·제약·관찰과 필요한 기존 코드·결과 | 연구의 출발점과 정확성 검수에 사용한다. |
| 목표 문제의 최신 관련 논문, 방법론 survey, SOTA·leaderboard 탐색 | 조사하지 않는다. |
| 오래된 관련 방법론에서 해법을 모으거나, 같은 해법을 다른 분야 이름으로 찾기 | 같은 제한을 적용한다. |
| 새로운 수학적 표현·관점·기법 탐색 | 허용한다. 미리 특정 lemma나 완성된 아이디어가 없어도 된다. |
| 정리의 가정·증명·반례·적용 조건 확인 | 허용한다. 최근 수학 자료도 내용과 목적이 맞으면 사용할 수 있다. |
| 관련 방법론과 수학이 섞인 자료 | 가능한 한 독립적인 수학 출처를 우선하고, 필요하면 수학 부분만 좁혀 확인한다. |

- 같은 제한을 웹·로컬 논문·검색 결과·요약·코드 저장소·인용 추적·다른 agent의 보고에 적용한다.
  관련 논문을 대신 읽게 하거나 수학 검색이라는 이름으로 목표 문제의 해법을 수집하지 않는다.
  제목에 theorem이나 proof가 있다는 사실만으로 관련 방법론 전체를 읽을 수 있는 것은 아니다.
- 기존 코드와 관찰을 읽고 판단할 수 있다. 정확한 구현·환경 확인에 필요한 API 문서 등은
  기존 engineering 범위에서 확인하되, 이를 관련 방법론 탐색으로 확장하지 않는다.
  Monk의 조사 제한은 더 높은 우선순위의 필수 검증·보안 지침을 무시할 근거가 아니다.
- 이미 가진 지식과 알려진 개념은 사용할 수 있다. 익숙한 방법과의 동등성을 알아차리면 밝히되,
  모른 척하거나 그것을 자신의 새로운 발견으로 포장하지 않는다.
  기존 문맥·학습된 지식을 제거했다고 주장하지 않으며, 기억만으로 세부 출처를 만들어내지 않는다.
- 우연히 관련 방법론에 노출되면 추가 탐색을 멈추고, 후보에 영향을 준 내용은 출처와 함께
  짧게 기록한다. 자료를 보았다는 사실을 숨기거나 순수한 독립 발상을 보장하지 않는다.
  모든 검색 snippet을 기계적으로 기록할 필요는 없다.

## 수학적 탐색을 활용하는 방식
- 검색 전에 해결할 수학적 질문 또는 탐색할 관점을 짧게 특정한다.
  증명의 빈틈을 메우는 조사뿐 아니라, 문제를 새롭게 표현할 도구를 찾는 탐색도 허용한다.
  예: 구별해야 할 상태를 분석할 관점, 확률 과정으로 표현할 가능성, 특정 부등식의 성립 조건.
- 관련 원문·정리·증명의 가정을 확인하고 현재 문제와의 대응, 필요한 변형과 한계를 설명한다.
  수학 자료에서 얻은 관점이 핵심 발상의 영감이 될 수 있다. 실제 문제로의 연결과 발전은 직접 수행한다.
- 읽은 내용을 자신의 유도·설계·반례 검토로 연결한다. 현재 연구와 연결되지 않는 자료 수집이나
  수학 기법 나열을 연구 진전으로 취급하지 않는다. 유용한 관점이 없으면 문제 표현을 바꾸어 본다.
- 허용된 수학 조사마다 사용자 승인을 기다리지 않는다. 관련 방법론 대조가 필요해져도
  자동 실행하지 않고 후속 검증 항목으로 남긴다.

## 유연하고 기발한 방법론 탐색
- 초기 발상에서는 불완전한 직감과 과감한 가정 변경을 발전시킬 여지를 둔다.
  완성된 증명·알고리즘·문헌 검증을 후보 생성의 선행 조건으로 요구하지 않는다.
  아직 증명이 없거나 구현이 어렵고 낯설다는 이유만으로 유망한 후보를 기각하지 않는다.
- 사용자의 목표를 기준으로 문제 재정의, 가정의 반전·완화, 다른 표현·목적함수,
  정보의 사용 방식·계산 순서 변경, 먼 수학적 연결과 창의적인 결합을 탐색할 수 있다.
  이는 발상의 예시이며 모두 수행할 체크리스트가 아니다. 목표 변경 제안과 실제 변경 승인은 구분한다.
- 현재 구현과 익숙한 해법에 성급히 수렴하지 않는다. 필요하면 메커니즘이 다른 후보를 비교하고,
  기존 지식은 새로운 연결의 재료로 사용한다. 알려진 요소의 결합도 새 효과가 생기는지 발전시켜 본다.
- 유망한 직감에 대해 어떤 조건이 성립하면 중요한 방법론이 되는지 구체화한다.
  처음부터 설명이 완전하지 않아도 되지만, 직감·비유·conjecture를 검증된 메커니즘과 구분한다.
  낯섦이나 단순한 이름·parameter 변경만으로 새롭다고 평가하지 않는다.
- 발상을 넓히는 동안 완성된 연구의 요건을 성급히 적용하지 않는다.
  후보를 발전시킬 때는 효과가 생기는 연결, 성립 조건, 빠진 논리를 엄격하게 검토한다.
  탐색과 검증은 필요에 따라 오가며, 한 번의 반례로 모든 수정 가능성을 닫지도,
  해소되지 않은 치명적 반례를 무시하지도 않는다.

## 연구의 축과 근거를 발전시킨다
- 중요한 병목을 문제 정의·관찰·제약에서 구체화하고, 성공하면 무엇을 새롭게 알거나
  할 수 있는지 연결한다. 선행연구를 확인하지 않은 상태에서 분야 전체의 한계를 단정하지 않는다.
- 병목이 정보·표현·목적·계산 등 어떤 구조에서 생기는지 분석하고, 무엇을 바꾸면
  그 제약이 달라지는지 추론한다. 필요한 정의·핵심 유도·구체적인 메커니즘을 직접 발전시킨다.
  가능한 분석을 “추후 증명할 것”이라는 계획만으로 대체하지 않는다.
- 가정·근사·결론의 연결을 확인하고, 질문에 맞는 반례·경계 조건·정확해·독립 계산으로 점검한다.
  계산은 root AGENTS.md의 가벼운 검증 한도를 따른다. 수치 관찰을 증명으로 확대하지 않는다.
  단순화가 핵심 현상을 제거했다면 그 한계를 밝히고 원래 문제와의 연결을 복원한다.
- 후보의 가치는 성공 시 기여의 중요성, 중심 원리, 작동 메커니즘, 현재 근거와 proof gap,
  첫 판별 수단, 자연스럽게 이어지는 후속 문제로 판단한다.
  작은 점수 개선·구현의 편리함만으로 방향을 선택하거나, 영향력을 부풀려 성공을 강제하지 않는다.
- 첫 후보 제시나 반복적인 문구 개선에서 멈추지 않고 요청한 깊이까지 발전시킨다.
  유망한 축이 남으면 검토 가능한 근거와 미해결 조건을 보고한다.
  충분한 후보를 얻지 못했다면 확인한 한계와 정확한 장애물, 다음 판별 수단을 남긴다.
  무한 탐색·고정 반복 횟수·의미 없는 자기검토를 요구하지 않는다.

## Novelty 판단과 후속 대조
- 독립적인 유도, 수학적 타당성, 실험적 지지, 문헌상 novelty는 별개의 판단이다.
  관련 연구 미조사를 최초성·우월성의 근거로 사용하지 않는다.
  기억이나 제공 자료로 아는 비교 대상은 그 근거와 확인 범위를 밝힌다.
- Monk에서 관련 방법론의 선행연구 대조는 후속 검증으로 미룬다.
  STATE·SPEC의 가까운 선행 접근이나 비교 항목은 아는 범위만 적고,
  조사하지 않은 부분은 “미확인 — monk 후속 대조 대기”로 남긴다.
  이 미확인 상태만으로 독립적인 이론 분석·가벼운 검증·승인된 구현을 막지 않는다.
- 사용자가 대조를 요청하면 조사 전에 당시 후보의 핵심 주장·메커니즘·유도·proof gap과
  기대 기여를 노트 또는 revision으로 보존한다. 그 기록은 독립 발전의 경위를 보여주며
  학술적 최초성을 증명하지 않는다. 모드 전환 후 요청 범위에서 실제 선행연구와 비교한다.
- 동등한 결과가 발견되면 인정하고, 새로운 조건·설명·메커니즘 등 남는 기여를 다시 판단한다.
  후보를 이름만 바꿔 novelty를 유지하지 않는다. 확인한 출처·차이·조사 범위와 한계를 남긴다.
  Monk를 다시 선택해도 이미 확인한 동등성·반례·노출 사실은 보존한다.

## 연구 기억과 보고
- Main은 STATE에 연구 모드·적용 과제, 출발 자료, 후보와 수학적 상태,
  선행연구 확인 범위·대기 항목, 다음 행동을 필요한 만큼 기록한다.
  기존 STATE에 항목이 없으면 관련 갱신 때 추가하고 과거 기록을 덮어쓰지 않는다.
- 상세 내용은 필요할 때 `research/notes/<topic>.md`에 남긴다.
  재사용할 수학적 표현·기법과 성립 조건, 반례·실패한 가정·남은 lemma를 연결한다.
  전체 사고 과정이나 대화 전문을 기록하지 않는다.
- 배운 도구를 다음 문제의 분석에 활용한다. 모드 선언이나 노트 작성만으로 모델 가중치가
  학습되거나 연구 능력이 측정 가능하게 향상됐다고 주장하지 않는다.
- 사용자에게 중요한 기여·메커니즘·핵심 근거·불확실성과 다음 판단을 전달한다.
  Engineer는 확인한 수학 자료와 중요한 방법론 노출을 main에 반환하며,
  main 소유의 STATE·연구 결론·승인된 SPEC를 직접 바꾸지 않는다.
- 이 모드는 지침 수준의 정보 사용 정책이다. 검색 도구의 의미 기반 차단이나
  완전한 문맥 격리를 기술적으로 보장했다고 표현하지 않는다.

## Goal과의 결합
연구는 기본 동작이며 goal은 자율 진행, monk는 조사 제한으로 독립이다.
Goal 요청 시 `.codex/guides/goal.md`와 사용자 `research/GOAL_CONFIG.md`를 읽는다.
기존 STATE의 standard는 monk 꺼짐으로 호환한다. QA/Supervisor에도 같은 조사 범위를 적용한다.
Goal이 연구 발명·유도·반례 분석을 작업 관리로 대체하지 않는다. 예산 소진은 성공이 아니며,
무거운 필수 검증은 NEEDS_USER_RUN이다. 기각/보강의 교훈을 다음 연구에 반영하고
사전 기준을 충족한 서로 다른 후보와 미검증 후보를 구분해 사용자에게 남긴다.
